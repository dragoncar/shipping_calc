# 运费计算器 v2.10

一个离线可用的 PWA 运费计算工具，输入重量和地址即可自动计算运费。

**线上使用：https://dragoncar.github.io/shipping_calc/**

## 功能

### 三种输入模式

- **单商品** —— 输入一个重量直接算
- **多商品** —— 填商品清单（名称 / 重量 / 数量），自动汇总总重
- **智能计算** —— 粘贴 1688 订单原文，自动提取货号、数量和收货地址，再从重量库匹配重量

### 其他

- **重量输入**：支持小数、中文逗号，快捷键（1/3/5/10/20kg，可自定义）
- **地址识别**：输入完整地址自动识别省份，也支持只输城市名/县名
- **重量库**：导入 Excel 货号重量表（存在本地），智能计算时自动匹配
- **不发快递提示**：新疆/西藏自动提示不发货
- **重置/复制**：一键清空、一键复制运费明细到微信
- **离线可用**：首次打开后完全离线可用（PWA），零外部依赖
- **数据持久化**：快捷键、重量库自动保存在浏览器本地

## 地址识别

基于官方行政区划数据，覆盖全国 **6170** 个地级市、县级市、县、区、旗。

识别规则：**看行政区划名出现的位置，越靠前越可信，位置相同取更长的**。

因为地址基本都是「省 市 区/县 街道」的顺序，开头就是省份，所以：

```
陕西省商洛市商南县城关街道   → 陕西（不是西藏）
拉萨市城关区北京中路        → 西藏（不是北京）
重庆市天津路               → 重庆（不是天津）
```

街道名、路名不会抢走真正的省份。

## 计价规则

### ≤ 12kg

| 地区 | 单价 |
| --- | --- |
| 甘肃、宁夏、云南、广西、青海、贵州、海南、内蒙古 | 5.5 元/kg |
| 其他地区 | 3 元/kg |

### > 12kg

**特殊地区价**（重量 × 费率 + 10 元基础费）：

| 费率 | 地区 |
| --- | --- |
| 4 元/kg | 海南 |
| 2.5 元/kg | 甘肃、青海 |
| 2 元/kg | 云南、宁夏 |
| 1.8 元/kg | 四川、福建、吉林、广西、贵州、舟山、延安 |

**其他地区走常规阶梯价**（1.5 元/kg）：

| 重量 | 计费方式 |
| --- | --- |
| 13–15kg | 按 15kg 计费 → 15×1.5+10 = ¥32.5 |
| 16–20kg | 按 20kg 计费 → 20×1.5+10 = ¥40 |
| 21–89kg | 实重 × 1.5 + 10 |
| ≥ 90kg | 实重 × 1.5（不收基础费） |

新疆、西藏不发快递。

直接打开 https://dragoncar.github.io/shipping_calc/ 即可。

## 更新日志

### v2.10 — 2026-09-29

- **重写重量库导入：改成「认表头」而不是「认行」**。只在前 20 行里找同时含「产品型号」和「重量」的那一行，拿到这两列的**列号**之后，表格有多少列、中间夹了多少无关列、合并单元格怎么规划、一个产品占几行，全都不用管。找不到表头才退回「前两列」的老约定。
- **修复只导入 8 个货号**（实测这次的文件应该进 91 个）。两个原因叠加：
  1. 旧代码把工作表 `sheet_to_csv` 序列化成文本，再用 `split(/[,\t]/)` 裸切。图片列是 `=DISPIMG("ID_xxx",1)` 公式，导出成 CSV 后外面套了引号，**格内的逗号被当成了分隔符**，导致该行从第 3 列起整行右移一格 —— 型号格读到「款式」、重量格读到「材质」，全被丢掉；少数行的材质格恰好是数字，就变成 `pu`、`牛津布`、`胸包` 这种脏货号混进库。
  2. 该表每个产品占 6 行（6 个店铺/价格档），型号和重量是 `D3:D8` / `H3:H8` 的**纵向合并单元格**，值只在每组首行 —— 497 个数据行里 425 行的型号格是空的，旧代码 `if (!model) continue` 直接跳过。
- **xlsx 改走二维数组，不再绕 CSV**。`sheet_to_json(ws, {header: 1})` 直接按列号取值，从根上避开序列化再切分。
- **CSV 分支补上 RFC4180 解析**（`parseCSVRows`）：引号里的分隔符和换行都不算数。另存为 CSV 再导入会踩同一个坑，现在也修了 —— 顺带解决了「一个格里用换行挤了多个货号」被切碎的问题。
- **一个格里的多个货号按换行拆开**，各自登记同一个重量。
- 导入结果提示改成「新增 X 个 / 更新 Y 个 / 共 Z 个」，并把**表里没填重量而跳过的货号列出来**（这次的文件里是 `508USB`、`Y632-1`）。
- 验证：`shipping_calc_test/import_test.mjs`（真实 45MB 文件，xlsx 与 CSV 两路各 91/91、零差异）、`import_edge.mjs`（16 条边界用例）、`e2e_import.mjs`（真实 Edge 无头 + 真实 file input，1.3 秒、无报错）。

## 开发

纯前端项目，零构建、无 npm。直接改 HTML/CSS/JS 刷新即可。

```bash
git clone https://github.com/dragoncar/shipping_calc.git
cd shipping_calc
# 用浏览器打开 index.html，或起个本地服务
python -m http.server 8899
```

### 项目结构

```
index.html            主页面
app.js                全部逻辑 + 内嵌省市数据（约 7000 行）
styles.css            样式
sw.js                 Service Worker（离线缓存）
使用说明.html          给用户看的图文说明
vendor/xlsx.full.min.js   SheetJS 0.18.5，仅导入 Excel 时用
```

### 改动注意事项

1. **改完必须 bump `sw.js` 里的 `CACHE_NAME`**，否则老用户永远拿不到更新（fetch 是 cache-first）。
2. **`PRECACHE_URLS` 只能放同源文件**。混入跨域 URL 会让 `cache.addAll` 整体 reject，Service Worker 直接装不上，离线功能全废。
3. **不要在 `<script>` 里同步加载外部资源**。defer 的 `app.js` 会被它阻塞，导致整页交互失效。
4. **面向国内用户，不要引国外 CDN。** 第三方库一律 vendor 到仓库内。
5. 本地验证改动时注意 **Service Worker 会喂旧文件**，刷一次可能还是旧版：

```js
// 在页面控制台执行，然后刷新
const regs = await navigator.serviceWorker.getRegistrations();
for (const r of regs) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
```
